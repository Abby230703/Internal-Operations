FIX: "You can't set the number format of cells in a typed column"  (adding a stock top-up, and two related spots)
========================================================================================

Cause
  Your sheet's tables have TYPED columns (date, drop-down, number). The sheet refuses a number format on a typed column,
  and writing a JavaScript Date into a typed DATE column makes it try. Two columns the new code wrote dates into are typed:
     Requirements > Req Date          (the Stock top-up)
     Sales Order Lines > Dispatch Date (dispatching an order; would have failed the same way)
  The fix writes those dates as their serial number: the column shows it in its own date format.

  The same table definitions showed two more mismatches, fixed here too:
     GRN Lines > Stickered is a drop-down (Done / Left); the code was writing TRUE / FALSE.
     Stock Movement > Type drop-down says "Audit adj." (with the dot); the code wrote "Audit adj".

Three files change: Items.gs, Procurement.gs, Warehouse.gs. Apply each edit: find the FIND block (it is unique in the file),
replace it with the REPLACE block. Then redeploy a new version.

Also check (Db.gs, not changed here): it must still contain this guard. If it does not, add it.
     setFormat_: function (range, f) {
       try { range.setNumberFormat(f); } catch (e) { /* typed column - keeps its own format */ }
     },
  and Db.append / Db.update must call Db.setFormat_(...) instead of calling range.setNumberFormat(...) directly.

Optional, Sales side: ReqApi.create (RequirementsApi.gs) writes  'Req Date': U.today()  into the same typed column. If
"Save requirement" on the Sales Requirements screen ever shows the same message, change that one value to
     'Req Date': Rows.serial(U.isoToday())
(Rows.serial is defined by the Items.gs edit below.)
